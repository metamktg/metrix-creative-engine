DOUBLE-CLICK  GO.cmd  IN THE FOLDER ABOVE THIS ONE.
===================================================

That is the whole thing. It updates itself, installs what is missing, finds
your briefs and reference images, and starts Claude Code.

Then paste this one line into Claude Code:

    Read sprint/GO.txt and do exactly what it says.


IF YOU HAVE NOT CLONED THE REPO YET
===================================

Open Command Prompt and paste these, one line at a time:

    git clone https://github.com/metamktg/metrix-creative-engine.git

    cd metrix-creative-engine

    GO.cmd


WHERE YOUR FILES GO
===================

GO.cmd looks in Downloads, Desktop and Documents for the briefs .json and
copies it in. It identifies a briefs file by reading it, not by its name.

Reference images are NOT taken from those folders - they are junk drawers, and
sweeping one put 1,381 images into a render set once. Either:

  * put the product images in a folder of their own and run
        GO.cmd -Source "C:\path\to\that\folder"
  * or let it pull the brand kit's own verified asset URLs, which is the
    default when nothing local qualifies.

More than one briefs file lying around? Name the one you want:

    GO.cmd -Briefs "C:\Users\You\Downloads\that_one.json"


WHY A .cmd AND NOT INSTRUCTIONS
===============================

Every failure on 2026-09-16 was a shell or a folder, never the work:

  "fatal: not a git repository"
  "sprint\setup.ps1 ... does not exist"
        A new terminal opens in your user profile, not in the repo.
        GO.cmd goes to its own folder first, so this cannot happen.

  "npm.ps1 cannot be loaded because running scripts is disabled"
  "claude.ps1 cannot be loaded because running scripts is disabled"
        PowerShell's execution policy blocks .ps1 wrappers.
        GO.cmd calls npm.cmd and claude.cmd, which it does not block.

  "The term 'it' is not recognized"
        A paste dropped its first character: "git" arrived as "it".
        PowerShell disables PSReadLine when it detects a screen reader.
        Double-clicking a file pastes nothing, so this cannot happen.

  Explorer opened Documents instead of the folder asked for
        $HOME does not expand in cmd.exe. GO.cmd uses no variables.
