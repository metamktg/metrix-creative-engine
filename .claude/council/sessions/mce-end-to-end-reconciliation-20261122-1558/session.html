Architect Position — MCE end-to-end reconciliation (brief JSON to launch-ready creative, every format, CI green)

Core recommendation: Build the data spine before any new format: a mce.formats/1 registry (one row per asset_type) and a mce.run/1 append-only manifest where every stage writes a schema-stamped, hash-bound report, so review can only pass what QA passed and handoff can only ship what review signed. Then express post-production (VO, music bed, SFX, GFX layers, transitions, cuts, captions) entirely as fields in mce.timeline/2, so every editorial decision is checkable by a script in CI rather than living only in composition HTML.

Key argument: The engine already has strong stage-local contracts (16 mce.*/N schema ids across timeline, cutplan, phrasemap, zones, eyestate, asrcheck) but no contract between stages, which is exactly where every one of the audit's broken handoffs sits. The shape of the data tells you the fix: (1) the brief is stripped at the door because briefSchema is a plain z.object and declares neither testing_framework.cells nor matrix_naming_convention, which make-row.mjs:33-34 hard-requires; (2) qa-video.mjs:428 prints its report to stdout with no schema id and no input hashes, so validate_review_gates.py (which binds artifacts by sha256 only) has nothing to bind; (3) format knowledge is keyed by asset_type in at least four code places (ASSET_TYPES/MOTION_TYPES in src/brief.ts, FORMAT_MODULES plus the hard-coded requiresProductionReview list in src/prompts.ts:85, storyboard kind, the zone table) and they already disagree (claymation is in ASSET_TYPES but not in MOTION_TYPES; carousel has a storyboard kind nothing renders). One registry row per format, read by brief, prompts, storyboard check, render, QA and review, removes drift by construction; one run manifest that each stage appends to (inputs by path+sha256, outputs by path+sha256+schema, verdict) turns "proof on every technical claim" into a mechanical property. Post-production completes the picture: the timeline schema already models clips, shots, scenes, cut points, caption groups, audio.voice, audio.sfx[] and audio.music.sections[], and audio-graph.mjs already sidechain-ducks music under voice, but there is no field for transitions or GFX layers (zero matches for transition/gfx/overlay in timeline/schema.mjs), so those agency-quality details are unverifiable today. Adding optional transitions[] (bound to cut point ids) and gfx[] (layer, from/to refs, zone id, copy source) to mce.timeline/2 lets timeline check, render --mode check and qa-video assert them the same way they already assert captions. Every addition is an optional field or a new schema id, so nothing existing breaks.

Risks if ignored:

  • Structural/data: new formats (static-compose, shopping/DPA, carousel, VO, b-roll, ingest) each re-encode format rules in another place, raising the six-place drift; a shopping price or carousel card count retyped instead of bound to the brief/feed by field path is a launch-blocking factual error the gates cannot see.
  • Integrity/performance: without hash-bound stage reports, a stale or failed QA artifact can satisfy review (proven gap: review never reads QA), and re-runs cannot be skipped safely, so every retry re-spends Kie credits on generations that already settled (the ledger holds the taskId, but no stage knows which output it fed).
  • Integration/migration: two Kie protocol implementations (src/client.ts+src/protocol.ts vs skills/metrix-ad-creative/scripts/kie.mjs, 374 lines) and non-Kie outputs (Higgsfield, Canva, direct Gemini/Veo, vendored media-use routing to HeyGen) mean spend and provenance live outside one ledger; the MST scan receives no receipt, so downstream cannot prove only the isolated slot changed.

Dependencies on other domains:

  • Craftsman: test design for the registry-consistency test (every registry row resolves to an existing prompt module, zone ids, QA and review gates), golden fixture briefs per format, and stubbed spend-path evals (Q10); owns keeping npm run verify the single gate.
  • Skeptic: failure modes of the run manifest (partial writes, hash of a file mutated after its stage, concurrent runs on one out/ dir) and of feed-bound shopping renders.
  • Advocate/Artisan (creative quality lens): the per-format quality bar that becomes registry qa/review gate lists, transition and GFX vocabulary (what kind values are allowed), caption style rules per placement.
  • Operator: CI runtime budget (Chrome render test cannot be skipped), plugin packaging and plugin validate in CI (Q9), and the environment variables that replace the X:/Metrix/... Windows defaults.
  • Owner / Metrix IAP: the versioned upstream brief JSON schema (Q3); until it exists we mirror field names exactly.

B3. Run manifest — out/runs/<run_id>/run.json

interface FileRef { role: string; path: string; sha256: string; schema?: string }
interface StageRecord {
  stage: "plan" | "generate" | "ingest" | "assemble" | "render" | "qa" | "review" | "handoff";
  seq: number; started_at: string; finished_at: string;
  tool: { name: string; version: string };      // CLI + package version or git sha

Invariants (each a test): a stage may run only if every input hash matches a prior output; review requires a qa record with verdict=PASS|WARN whose outputs include every artifact reviewed; handoff requires review PASS. Artisan Position — MCE end-to-end reconciliation (visual system, GFX, transitions, captions)

Core recommendation: Make the look a compiled, checked contract, the way placement zones already are. One mce.look/1 file per run (compiled from the brand kit: colour, type, caption style, motion and transition tokens) feeds the single Chrome renderer for every format (video, static-compose, carousel, shopping, motion graphic), and the render and QA gates measure the result (contrast, type floor, safe zone, transition-vs-timeline parity) instead of trusting the HTML author.

Key argument: The engine already proves the pattern works: placement-zones.json is one table with provenance, render.mjs now reads it through zoneFor() (skills/metrix-video-assembly/scripts/render.mjs:547), and the render check fails a box inside the overlay bands. Everything else visual is still hand-authored and unchecked. The composition template hard-codes its palette and fonts (assets/template/index.html:21-27: --bg #f4efe6, --ink #101010, --accent #8a5a2b, @font-face commented out), and no script reads brand-kit.json into CSS (grep for var(-- across assembly and ad-creative scripts: zero hits). There is no contrast check anywhere in render, render-checks or qa-video, so white captions with a 45% shadow (.on-image, template line 37) over a bright Kie frame pass every gate. Transitions live outside the timeline: the runtime supports cut|fade|dip|slide|zoom per scene and defaults to dip (runtime.js:11,63-64), but the timeline schema only knows points of kind cut|event (timeline/schema.mjs:109), so timeline emit cannot produce a transition, the template dips between every scene by default, and qa-video transitions.at_cuts assumes hard cuts and would flag a fade crossfade as double exposure (qa-video.mjs:32-34). SFX carry at and why (schema.mjs:134) but are not bound to the transition or text slam they accent. Top-tier agency finish is not more effects; it is a small vocabulary used with intent and verified frame by frame: hard cuts on beat by default, a motivated transition only at a role change (hook to show, proof to offer), every whoosh tied to the transition it sells, captions in one house style with a plate or stroke that clears contrast on the worst pixel under them, and the same type scale and tokens on the static, the carousel card and the end card. Putting this into the format registry (Q4) and the run spine (Q2) means every format reads the same look and every gate proves it.

Risks if ignored:

  • Visual drift across formats: each static, carousel card, SKU overlay and video end card gets its own one-off CSS, so the same campaign ships three type scales and two reds, and carousel seams do not line up.
  • Unreadable captions and CTAs ship green: no gate measures text contrast against the generated background, and model frames vary per take, so legibility is luck. The only type check is a size floor (W * 0.03, render.mjs:548, duplicating min_font_ratio in the zones table).
  • Transition and SFX choices stay unreviewable: they are authored in HTML attributes the timeline does not know, so timeline check cannot hold them to beats or roles, QA cannot tell an intended crossfade from a bad blend, and whooshes drift off their cuts.

Dependencies on other domains:

  • Architect: format registry (Q4) carries per-format look requirements (which tokens, which gates); run spine (Q2) records look.json by sha256 like other stage inputs; timeline schema gains an optional transitions[] (new field optional, per AGENTS rule).
  • Craftsman: vitest fixtures for the contrast check (known-bad white-on-white frame must FAIL, plated caption must PASS), a transition parity test, and a brand-kit compiler unit test; all inside npm run verify, no spend.
  • Advocate: caption readability standard (chars per line, CPS already in captionRules) and sound-off comprehension of the first second.
  • Skeptic/Operator: font licensing path for client brand fonts (only Google Fonts are installed; licensed faces come from kit files), and render-time budget for the extra contrast sampling.
  • Owner/Guardian (fact, not policy debate): brand-kits/eastcoastartstudio/ is git-tracked (git ls-files lists four files) and names a real account, while the map describes brand-kits as anonymous/sample; the look compiler should read kits from the private run dir, with an anonymous sample kit as the committed fixture.

Step 3: Specs

Hook text (first second, sound off) — Trigger: t=0 or first cut. Property: opacity + translateY / scale. From -> To: rise 0.6em->0 or slam scale 1.35->1. Duration: medium. Easing: enter. Must be settled by 1.0 s (existing line_unread craft check). Caption cue — Trigger: phrase start from phrase map. Property: opacity; active word colour. Duration: micro. Easing: enter. Architecture

Data spine (Architect).

  • mce.formats/1 lives at skills/metrix-ad-creative/references/formats.json. Each row carries asset_type, medium, motion, required_brief_fields, placements, prompt{module,review}, plan{storyboard_kind}, route, look{slots[],gates[]}, qa[], review[], handoff{receipt,mst_row}. A build step generates the brief enum. A vitest consistency test, extending single-definition.test.ts, fails on any drift or on a missing fixture dir.
  • mce.qa/1 is written by qa-video --out <file> as {subject{sha256}, inputs, checks[], verdict, exemptions?}. validate_review_gates.py adds a required artifact role qa_report. Review FAILs if the report is absent, if its sha does not match the master under review, or if the verdict is FAIL.
  • mce.run/1 records each stage's inputs and outputs by path, sha256 and schema. A stage runs only if each input hash equals a prior stage's output. Writes use temp-file plus rename. A re-run with the same input hashes and a PASS record is a no-op, so resume costs no credits.
  • mce.mjs run init|plan|generate|ingest|assemble|render|qa|review|handoff|status shares one error contract:
ErrorExit code
GATE_FAIL1
CONTRACT_SCHEMA, CONTRACT_HASH, TOOL_MISSING2
BLOCKED_ASSET, BLOCKED_SPEND3

run status prints the manifest chain from the brief through ledger task ids, QA and review records.

  • Handoff loads 03-handoff.md, requires review PASS and writes mce.receipt/1 listing every deliverable sha256.
  • One ledger. Every non-Kie output (Gemini/Veo, Higgsfield, Canva, HeyGen, desktop edits) re-enters through run ingest with provider, run_id and file_sha256, then goes through the same QA and review.
  • Packaging. Add .claude-plugin/plugin.json (16 skills) and run plugin validate in CI. An MCE_* env/manifest resolver replaces the X:/ defaults. brand_assets accepts an array or {items, missing}. One Kie client is bundled from src/ into the three kie.mjs paths via skill-copies.json.
  • Compatibility. All brief and timeline changes are optional fields. New contracts get new schema ids. Byte copies are edited only at their canonical path. Client data stays in gitignored out/ and renders/.

User Experience

Look, GFX, transitions, captions, SFX (Artisan).

  • Look as a contract. mce.look/1 is compiled by a pure look compile from a private brand kit into --look-* CSS custom properties, passed through window.__MCE. The raw hex/px values in assets/template/index.html:21-27 become var(--look-*). The token set is small: about 12 primitives, 6 semantics and 5 components, and any token no format slot reads gets cut. Video, static-compose, carousel cards, shopping overlays and the end card all read one look through one renderer. The static and poster are the settled frame of the same composition.
  • Transitions as data. Each entry in transitions[] is {id, at: cut-point ref, kind: cut|fade|dip|slide|zoom, frames: int, why}. The kinds are exactly the enum runtime.js:11 implements. Durations use the house scale 0/4/8/11/15 frames. A kind other than cut is allowed only at a ROLES boundary (hook/show/proof/offer/cta) or with a bound SFX. slide covers push, and a whip is slide plus a bound whoosh. emit always writes data-trans-in/out on both adjacent scenes, with cut as the default.
  • SFX binding. sfx[].bind is optional and names a transition id or text id. timeline check requires sfx.at to equal the bound anchor, and QA checks that the onset falls within onsetGuard (rules.mjs:57).
  • GFX. Each entry in gfx[] is {id, layer, from, to, zone, copy_source?}. Shopping/DPA prices are bound to the feed SKU field and styled with badge.price.
  • Readability. Contrast is measured on the 95th-percentile worst background luminance under each text box at its settled frame, with plates and strokes counted as background. The floor is 4.5:1, or 3:1 for type at the large step of the scale. The type floor reads min_font_ratio from the zones table, replacing the hard-coded W*0.03 at render.mjs:548.
  • Motion specs.
  • Enters use cubic-out. Scene moves use cubic in-out. Back overshoot is for pop only.
  • Stagger is 3 frames with at most 5 items. The hook is settled by 1.0 s.
  • End card: logo at 15 frames, offer rise at +3 frames, CTA pop at +6 frames with its SFX bound. One pulse is allowed, no earlier than 1 s before the end.
  • Animate only opacity, transform and clip-path.
  • Format rollout order: static-compose, shopping/DPA, carousel (1 px seam), VO (ASR checked against the locked script.sha256), b-roll (shot list from timeline gaps), then ingest + grade.
