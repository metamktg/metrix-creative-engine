## Architect Response to Artisan

**Their position:** Make the look a first-class compiled contract, one `mce.look/1` per run built from `brand-kit.json` and injected into the single Chrome renderer for every format, with contrast, type-floor, look-parity and transition-parity gates added now, and a timeline `transitions[]` whose entries use a fixed frame-based duration/easing scale and carry the SFX that sells them.

**My response:** Modify

**Reasoning:**
Artisan is right that look is its own contract, and I withdraw "look requirements as registry columns" as the whole answer: the data has two different grains. The registry is keyed by `asset_type`, ships with the repo and changes on release; a look is keyed by brand kit, lives in the private run dir (client data, so never a committed registry row) and changes per campaign. Putting token values in `mce.formats/1` would mix a per-format table with per-client data, so the clean split is: the registry row declares *which* look slots and gates a format needs (`look: { slots: ["caption.house","cta.button","endcard.logo","badge"], gates: ["contrast","type_floor","look_parity"] }`), and `mce.look/1` supplies the values, compiled by a pure `look compile` step and recorded in `mce.run/1` as a `FileRef` input to assemble/render, exactly like the cutplan and phrasemap already are. I also adopt the stricter transition model over my looser B7 sketch, with two corrections from the code. First, vocabulary must match what `runtime.js:11` actually renders (`cut|fade|dip|slide|zoom`; my `dissolve|whip|match|wipe` had no implementation, and Artisan's `push` is the runtime's `slide`), so `kind` is that enum and new kinds land with their runtime branch in the same PR. Second, durations are stored as integer frames against the timeline's existing `fps` field (`schema.mjs:94/147`), drawn from the house scale (0, 4, 8, ~10.5 -> round to 11 at 30 fps for the 0.35 s medium, 15), with `timeline check` rejecting off-scale values and a transition longer than the adjacent min shot; `sfx[]` gains optional `bind: { transition | text }` and `check` asserts onset within `onsetGuard` of the bound event. Transition parity needs no new QA mechanism: `qa-video` already accepts `mce.qaexempt/1` windows for `transitions`/`transitions.at_cuts` (`qa-video.mjs:47,66`), so `timeline emit` derives exemption windows from declared `transitions[]` and an undeclared blend still fails; `emit` must also write `data-trans-in/out` explicitly, because the runtime default is `dip` (`runtime.js:63-64`) and an unannotated scene silently dips today. Where I maintain is order of *merging*, not of *building*: the look compiler, its fixture kit, and the contrast check against a known-bad white-on-bright frame are pure, no-spend and can be built in parallel now under Q1, but the contrast gate and look parity must not merge as stdout-only verdicts, because `validate_review_gates.py` never reads `qa-video` output today and a fourth unread verdict is exactly the broken-handoff pattern the audit documents. So the sequence is: `mce.qa/1` file output plus review reading it, and the registry row shape, land first (small, no render.mjs contact); the contrast and type-floor checks then land inside `render --mode check` (render.mjs, so CI-gated per Q1) writing into `mce.qa/1`; `look.json` is hashed into the run manifest when the spine CLI lands. Two further points I keep: the type floor reads `min_font_ratio` from `placement-zones.json` and the `0.03` literal at `render.mjs:548` is deleted, one source; and Artisan's flag that `brand-kits/eastcoastartstudio/` is git-tracked is a data-boundary defect that blocks committing any compiled look fixture from it, so the committed fixture is an anonymous sample kit and real kits are read only from the gitignored run dir.

**Compromise proposed:**
| Contract | Owner | Grain | Where | Recorded in |
|---|---|---|---|---|
| `mce.formats/1` row `.look.slots/.gates` | Architect | per format | repo | registry_sha256 |
| `mce.look/1` values | Artisan | per brand kit per run | `out/runs/<id>/look.json` | `mce.run/1` FileRef |
| `mce.timeline/2.transitions[]` (runtime enum, integer frames, house scale) | Artisan vocab, Architect schema | per edit | run dir | timeline sha256 |
| `audio.sfx[].bind` | Artisan rule, Architect field | per edit | run dir | timeline sha256 |
| contrast / type_floor / look_parity / transition parity verdicts | shared | per master | `mce.qa/1` | review artifact `qa_report` |
