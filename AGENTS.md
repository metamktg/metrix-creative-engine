# Creative workflow defaults

Use `skills/metrix-ad-creative/SKILL.md` when producing assets from an approved
Metrix brief. Preserve the brief's declared format, current user decisions,
accepted components and existing authorization.

For UGC, AI-UGC and video production or revisions, read the short
`prompts/07-ugc-creative-direction.md` before planning or spending. At planning
and review, read only the relevant stage of `docs/UGC_CREATIVE_PLAYBOOK.md`.
Use `prompts/06-production-review.md` and `docs/UGC_PRODUCTION_STANDARD.md`
for the existing finished-asset review contract. Apply creator-specific details
only where the format uses them.

MCP `kie_render_ugc`, `kie_render_ai_ugc` and `kie_render_video` include the short direction
and review modules. Their detailed playbook is `kie://ugc-creative-playbook`.
The standalone `metrix-ad-creative` skill bundles equivalent direction and
playbook references for use without this checkout or MCP. Send providers only
shot-specific instructions and supported fields, never the entire playbook.

Keep completed client profiles, copy, asset bindings and receipts in gitignored
`out/` or `renders/`, or an external private run directory. Shared instructions,
examples and fixtures stay anonymous; never populate the committed example
with client records. These workflow instructions add no spend or publishing
authority and do not change the raw generation API.

Before dependent approved-voice creator lip sync, validate the current private
preproduction packet with `kie_validate_ugc_preproduction` and submit through
`kie_create_ugc_lipsync`, or the bundled client's `ugc-check` / `ugc-start`.
The separate script check precedes voice spend. These guards validate local
bindings, not actual listening or final approval; raw task tools are unguarded.

# Working in this repository

Client asset/review/storage continuity follows
`skills/ugc-creator-edit/references/client-library.md`. Resolve the current private
library before historical source searches. At authorized milestones execute its
connector sync plan and verify readbacks, keeping source/review storage separate
from approved-final delivery. This is not a background watcher.

`npm run verify` is the gate. It runs, in order: `check:copies` (every byte copy
equals its canonical file), `check:production-standard` (the generated standard
equals its two sources), `typecheck`, `test` (vitest), `build`,
`check:mcp-surface` (drives the built bundle and checks its advertised tools,
resources and prompts), `test:production-review` (Python review-record tests),
`test:retention` and `test:client-library`. Run all of it before calling a change done. Do not copy a test
count or a tool count into prose; those scripts are the inventory.

A file that appears in more than one place has one canonical copy, listed first in
`scripts/skill-copies.json`. Edit the canonical file, then run `npm run sync:copies`.
Never edit a copy. The skills must stay installable one at a time, which is why the
copies exist. `docs/UGC_PRODUCTION_STANDARD.md` is generated by
`skills/ugc-creator-edit/scripts/build_standard_doc.py`; regenerate it, never edit it.
Installed skill folders are synchronized with
`node scripts/sync-copies.mjs --installed <skills dir> --write`.

A rebuilt bundle does not reach a running MCP server. Restart the client or the
server to load it.

Draft cleanup goes through `scripts/retain_drafts.py`: write a plan, review it,
then apply that exact plan. See `docs/draft-retention.md`.

Backend, brief schema and tool contracts change only when the task needs a field.
Say so in the change, and keep new output fields optional.
